# PRD：内置拖放中转（DropPoint）

项目：FileTabs
参考：https://github.com/GameGodS3/DropPoint
作者：Date 2026-10-18

## 一、背景与目标

拖拽文件时，如果源窗口和目标窗口都被最大化占用整个屏幕，用户必须临时拖出窗口、分屏或最小化某个窗口，操作成本高。DropPoint 的做法是：在屏幕上弹出一个临时的小托盘点，用户先把文件拖进去，再去切换到目标程序，最后把文件从托盘点拖出到目标位置，完成跨窗口拖放。

FileTabs 希望把这个能力内置进来，用户不需要再额外安装一个独立工具。

## 二、目标用户与核心场景

目标用户：日常在 Windows 上频繁用鼠标拖拽文件的用户，尤其是同时操作两个全屏程序（如资源管理器 ↔ 微信/QQ/网页）的用户。

| 场景 | 描述 |
|---|---|
| 跨最大窗口拖放 | 两个程序都全屏/最大化，中间没有可见桌面，先拖入托盘点再切换目标窗口拖出 |
| 跨虚拟桌面拖放 | 托盘点显示在所有虚拟桌面上，用户在桌面 A 拖入、切到桌面 B 拖出 |
| 多文件批量拖放 | 拖入多个文件后一次性拖出 |

## 三、功能需求

### 3.1 拖放中转窗（托盘点）

悬浮一个小窗口，作为文件拖放的「中转站」，核心行为参考 DropPoint：

1. 默认 190×190、无边框、圆角、置顶、始终可见于所有虚拟桌面（不抢焦点，或最小化对焦干扰）。
2. 左上角有一个关闭按钮（×），点击后关闭当前托盘点。
3. 地址栏右侧提供一个「DropPoint 拖放中转」按钮，点击后在 FileTabs 所在显示器上打开或复用托盘点。
4. 托盘点可移动：空托盘时按住整块任意位置拖动；已有文件时使用顶部拖动条移动，避免和「拖出文件」手势冲突。拖动后的位置只在本次运行记住，重启后回到右中。
5. 空状态：显示「拖放文件到此」的提示。
6. 拖入文件（支持文件与文件夹、多选）后，悬浮窗切换为「准备拖出」状态，展示文件图标和数量。
7. 用户从托盘点按住鼠标向外拖动，托盘点将已收纳的文件以系统 OLE 拖放形式释放到目标程序。
8. 拖出完成后托点位自动关闭并清空状态。
9. 同一个文件夹重复拖入时做去重（以绝对路径判断），不再重复累积。
10. 同时最多打开 3 个托盘点；已有空托盘时优先复用并置顶，不再新建空框。
11. 新建托盘点时，初始位置固定在该显示器工作区右侧、垂直居中，距右边缘约 24px；第 2、3 个托盘点分别向上错开约 12px、24px，并做屏幕边界修正。

### 3.2 全局快捷唤起

- 默认快捷键：`Shift + CapsLock`（与 DropPoint 一致，可在设置中修改或禁用）。
- 按下后在当前鼠标所在显示器上打开托盘点；位置同样按右侧垂直居中和实例错位规则计算。
- 已有空托盘时优先复用并置顶（保持它当前位置）；没有空托盘且未达到 3 个时新建；已达到 3 个时置顶最近使用的托盘点。

### 3.3 托盘菜单

在系统托盘新增一个图标（若尚未存在），提供菜单：

- 新建 / 显示托盘点（按鼠标所在显示器定位）
- 启用/禁用拖放中转（写设置）
- 退出 FileTabs（保留原有行为，不强制退出）

### 3.4 设置页

新增「拖放中转」分区：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| 启用拖放中转 | bool | true | 总开关，关闭后不再响应快捷键、不显示托盘入口 |
| 全局快捷键 | string / 枚举 | Shift + CapsLock | 提供几个内置候选，支持自定义组合键（阶段 2 可延后） |
| 快捷键行为 | 枚举 | 新建 | 新建 / 切换 |
| 托盘点大小 | int | 190（P0 固定） | 后续阶段再提供 140 / 190 / 280 选项 |
| 关闭时保留托盘点 | bool | false | 主程序退出后托盘点是否继续可用（见 3.5） |

> P0 只实现「启用拖放中转」总开关；快捷键行为、托盘点大小和独立进程保留到后续阶段。

### 3.5 生命周期

- **简单实现（默认）**：托盘点作为 FileTabs 主窗口的内嵌子窗存在，主进程退出则所有托点位一并退出。
- 后续可考虑独立进程模式：把托盘点放在一个轻量子进程里，主窗口关闭时托盘点仍可用。阶段 1 不做。

## 四、交互细节

### 4.1 视觉

- 与 FileTabs 现有 Fluent 风格一致，跟随浅色 / 深色 / 跟随系统主题。
- 空状态用淡色提示文字 + 图标；收纳后显示文件图标（按文件类型选图片：图片/文本/音频/视频/文件夹/其他），多文件时做小幅倾斜层叠动画提示「多文件」。
- 拖入悬停时边框做一次虚线 inflight 动画（参考 DropPoint 的 `dragged` 关键帧）。

### 4.2 光标与焦点

- 托盘点 `Focusable=false`，避免遮挡输入或者抢焦点。
- 显示方式为 `Topmost=true`，且通过 `WS_EX_NOACTIVATE` / `WS_EX_TOOLWINDOW` 避免抢焦点、避免出现在任务栏。
- 不阻挡被覆盖窗口的键盘输入，但自身接收拖放事件。
- 空托盘时整块可拖动；收纳文件后顶部拖动条可移动，点击内容区则开始拖出文件。

### 4.3 多显示器

- 地址栏按钮以 FileTabs 主窗口所在显示器为基准；全局快捷键和托盘入口以鼠标所在显示器为基准。
- 新建托盘点默认放在目标显示器工作区的右侧垂直居中位置，再按当前显示器上的实例槽位向上错开；若该槽位已有本次运行的位置缓存，则恢复缓存位置。
- 位置越界时自动收缩到该显示器工作区内；拖动后的位置只保留在当前进程运行期间。

## 五、非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 快捷键唤起到托点位出现 < 100ms；无常驻后台循环 |
| 内存 | 每个托点位窗口不持有额外大资源 |
| 可靠性 | OLE 拖入应同时支持 `FileDrop` 和文件夹；失败要在托盘点上短暂提示（不做弹窗） |
| 安全 | 仅保存文件 `FileSystemPath`，不读取文件内容 |
| 崩溃隔离 | 托点内部异常不应影响 FileTabs 主窗口 |

## 六、验收标准

1. `Shift + CapsLock` 在任意程序前台时，能在鼠标所在显示器右侧垂直居中位置打开托盘点。
2. 从资源管理器拖入多个文件/文件夹，托盘点显示文件图标与数量。
3. 从托盘点按住左键拖到微信聊天框、浏览器文件上传按钮、另一台窗口固定区域都能正常落文件。
4. 重复拖入同一文件，托盘点不会重复累积。
5. 拖出完成后托盘点关闭；多文件批量拖出后一次释放所有文件。
6. 关闭主窗口后，托盘点不再出现（阶段 1 行为）。
7. 设置里关闭「启用拖放中转」后，快捷键不再生效，托盘图标和地址栏按钮隐藏。
8. 切换主题（浅色 / 深色），托盘点视觉同步变化。
9. 地址栏按钮能按 FileTabs 所在显示器新建托盘点；空托盘可整块拖动，收纳文件后可用顶部拖动条移动。
10. 连续唤起的托盘点最多同时存在 3 个；存在空托盘时复用并置顶，不重复新建空框。
11. 新建的第 2、3 个托盘点分别比右中基准位置上移约 12px、24px，且不会越出工作区。
12. 用户拖动托盘点后，同一进程内再次使用该托盘点时保留位置；重启 FileTabs 后回到右中位置。

## 七、超出本期范围（Out of Scope）

- 独立进程托盘、FileTabs 退出后仍保留中转（阶段 2）。
- 像 Dropover 那样的 gestural 全屏唤起、气泡包裹动画。
- 文件预览、搜索、批量重命名等扩展功能。
- 历史托点记录。

## 八、风险与依赖

* **OLE 拖出实现**：WPF `DoDragDrop` 直接从悬浮窗出发时，被拖内容必须正确封装为 `DataObject`（`FileDrop` + `Filename` + `FileGroupDescriptorW`），1 个文件时可用 `DoDragDrop`；多文件（多个路径）需要验证 Windows 对多个 `FileDrop` 路径的原生处理。
* **焦点抑制**：悬浮窗若抢走焦点，会打断正在进行的拖放操作；需要用 Win32 `WS_EX_NOACTIVATE`。
* **全局快捷键冲突**：`Shift + CapsLock` 是 DropPoint 默认，但部分键盘用户会按到；需要在设置中允许关闭或换键。
* **多显示器 / 虚拟桌面显示**：需要用 `WS_EX_TOOLWINDOW` + `SetWindowPos(HWND_TOPMOST)` 并让 DWM 认为这是一个浮动工具。跨虚拟桌面默认跟随，可能需要 `ShowOwnerOnAllWorkspaces` 或让窗口不挂在主窗口之下。
